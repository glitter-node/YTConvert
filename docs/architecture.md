# Architecture

The documented host deployment places an Nginx HTTPS reverse proxy before one Uvicorn worker on `127.0.0.1:8010`; other operators must verify their own proxy and network configuration. FastAPI serves the static interface and handles API validation, request IDs, safe JSON errors, allowed hosts, and structured access logs. The app factory and lifespan do not connect to a database, Redis, or FFmpeg.

Metadata analysis uses the yt-dlp Python API in a bounded thread. The URL validator accepts HTTPS watch, `youtu.be`, Shorts, and live links on known YouTube hosts, extracts one 11-character ID, and supplies a canonical watch URL to yt-dlp. yt-dlp runs with `download=False`, `skip_download=True`, `noplaylist=True`, disabled disk cache, no remote components, no JavaScript runtimes, eight-second socket timeout, and zero retries. The API has a 30-second wait limit and a two-extraction semaphore. A timed-out thread may continue until its network calls finish; it continues to occupy a semaphore slot. The API stores only bounded response fields, not yt-dlp's raw URLs or tokens.

The in-memory cache is keyed by video ID, expires after 600 seconds, and holds at most 100 successful snapshots. Concurrent requests for the same ID share one task. Failures are not cached. At most ten distinct analyses may be in progress or queued; excess requests receive 503. A per-client, in-memory 20-request-per-minute limiter covers analysis and format lookup. These limits are per API process and reset at restart.

The request URL check rejects arbitrary hosts, direct IP inputs, credentials, custom ports, playlists, and long URLs. The yt-dlp request guard checks outbound HTTPS service hosts but does not reject an approved host that resolves to a private or loopback IP. Library-managed redirects and DNS rebinding can bypass application-level checks; a root process is especially sensitive. There is no network isolation. This code alone is not a complete SSRF sandbox. Disabling JavaScript runtimes and remote components may reduce the formats YouTube exposes; no extra processes or remote components are enabled to improve coverage.

Format discovery maps actual yt-dlp stream records to codec, container, dimensions, bitrates, size, HDR status, and audio/video presence. Storyboards, mhtml entries, and entries with neither audio nor video are filtered. Unknown fields remain null. Video output options use distinct observed heights up to 4320p. Audio output bitrates among 128, 192, 256, and 320 kbps are shown only when a source bitrate supports them; unknown bitrate is identified as such. Video-only source streams carry a `requires_audio_merge` output flag when separate audio exists. MP3, M4A, and Opus are FFmpeg outputs, not invented source streams. FFmpeg encoder discovery runs when the app starts, including while the worker is disabled. The formats API marks outputs according to encoder support; job creation separately enforces worker readiness and encoder support. A missing VP9 encoder disables WebM without disabling other outputs.

The API persists a job record in `data/jobs`, then places its UUID on a single-process queue. One dispatcher runs at a time and identical active requests from one session are rejected. It spawns `app.workers.converter` in a new process group with the root identity inherited from Uvicorn. The worker receives a server-built task over stdin; client-supplied paths or command arguments are never accepted. It uses yt-dlp to download only selected source format IDs into `data/temp/{job_id}`, then ffprobe and FFmpeg to verify, merge, remux, or encode to `data/output/{job_id}`. FFmpeg is configured with two threads for its input and output stages and local input protocols; this is not a cap on every thread FFmpeg may create. The worker sets CPU, virtual address space, open-file, per-file size, and core-dump limits inherited by child processes. With the default 1,800-second job timeout, its CPU soft/hard limits are 7,200/7,205 seconds, virtual address space is 1.5 GiB, open files are limited to 64, core dumps are disabled, and each file is limited to the larger of the configured download and output size limits (1 GiB by default). These limits do not cap total disk use or provide network isolation. The API separately applies a wall-clock timeout and terminates the process group on failure or cancellation. Temporary files are removed after terminal outcomes; expired outputs are cleaned on startup and hourly when enabled. No media download or conversion process starts while the worker readiness gate is closed. These application limits do not constitute a privilege boundary against a compromised root worker.

The worker emits a structured failure event for yt-dlp, merge, ffprobe, FFmpeg, and final output checks. FFmpeg stderr goes to an unlinked per-job temporary file, avoiding a blocked stderr pipe; only the final 4 KiB are read on failure. The API drains the worker's own stderr concurrently with stdout, retains at most 4 KiB, and writes a redacted JSON log entry with job ID, stage, tool, exit code, timeout flag, exception type, and diagnostic. FFmpeg failures also log the CPU seconds consumed by that child and its CPU soft limit to help diagnose future limit hits. The persisted `error` field is a fixed safe message, preserving the existing JobResponse and SSE schema. A missing failure event or unexpected API-side exception is recorded as an unknown conversion failure rather than attributed to a specific tool. Historical records written before this diagnostic path retain only their original generic error.

The session cookie is random, HTTP-only, and same-site; its `Secure` attribute is set when the request URL scheme is HTTPS. Only its SHA-256 hash is stored with a job. The job ID is random but is not treated as authorization. The cookie scopes existing job access but is not an account system or an authorization check for job creation. `INTERNAL_IP_RANGES` gates only `POST /api/jobs`; metadata analysis and existing session-scoped job endpoints are outside that gate. SSE emits versioned `job` events and supports `Last-Event-ID`; a disconnected browser does not cancel work. Downloads check cookie ownership, completed state, the fixed per-job output path, symlink safety, file existence, and size. The worker is disabled by default in `app/core/config.py` and `.env.example`. There is no implemented outbound network isolation. Root-hosted yt-dlp metadata extraction and any future enabled download remain exposed to redirect or DNS rebinding risks that Python-level URL checks cannot completely prevent.

Job creation copies `MediaInfo.title` from the server-verified analysis snapshot into the persisted `source_title` field. The worker and internal output path continue to use the fixed `result.EXT` name. The download route applies a Unicode-preserving filename sanitizer to the stored title and passes the suggested name to Starlette `FileResponse`. Older records without `source_title` fall back to their media ID. This changes only the attachment name, not storage, session authorization, JobResponse, or SSE.

HTTP middleware applies trusted Host validation, sensitive-path denial, inbound IPv4/IPv6 CIDR blocking, security headers, CSP, and response cache rules. The blocklist is an optional project-local JSON array reloaded safely on change; it preserves the last valid content when a replacement is invalid. `request.client` comes from Uvicorn's loopback-only forwarded-header trust configuration. This inbound policy does not restrict the media worker's outbound connections. The UI uses external thumbnail images, so COEP is `unsafe-none` rather than cross-origin isolation.
