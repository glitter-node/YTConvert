# API contract

All errors use `{"error":{"code":"...","message":"...","details":null},"request_id":"..."}`. Validation errors return 422, invalid hosts return 400, rate limits return 429, extraction errors return 403/404/451/502/504, a client outside `INTERNAL_IP_RANGES` receives 403 `network_restricted` on a parsed job-creation request, and a disabled worker returns 503 after that check passes. Malformed JSON can return 422 before the network dependency runs. Every response includes `X-Request-ID`. Request bodies and query strings are not logged.

Trusted Host validation accepts `APP_ALLOWED_HOSTS`. Sensitive paths return 404 and blocked client IPs return 403. API and error responses use `Cache-Control: no-store`. Browser security headers and a CSP apply to all responses. `/openapi.json`, `/docs`, and `/redoc` are disabled by default; they are available only when `APP_ENV=development` and `APP_ENABLE_OPENAPI=true`.

| Method | Path | Input | Success | Current status |
| --- | --- | --- | --- | --- |
| GET | `/api/health` | None | `{"status":"ok"}` | 200 |
| GET | `/api/status` | None | Service and capability state | 200 |
| POST | `/api/analyze` | `{"url":"https://www.youtube.com/watch?v=dQw4w9WgXcQ"}` | `MediaInfo` | 200 or structured error |
| GET | `/api/formats/{media_id}` | 11-character YouTube ID | `FormatsResponse` | 200 or structured error |
| POST | `/api/jobs` | `CreateJobRequest` | `JobResponse` and session cookie | 201, 403 if network restricted, or 503 if worker unavailable |
| GET | `/api/jobs` | Session cookie | `{"jobs":[...]}` | 200 |
| GET | `/api/jobs/{job_id}` | UUID and session cookie | `JobResponse` | 200 or 404 |
| GET | `/api/jobs/{job_id}/events` | UUID and session cookie | SSE `job` events | 200 or 404 |
| POST | `/api/jobs/{job_id}/cancel` | UUID and session cookie | `JobResponse` | 200 or error |
| DELETE | `/api/jobs/{job_id}` | UUID and session cookie | Compatibility cancel alias | 200 or error |
| GET | `/api/download/{job_id}` | UUID and session cookie | Completed file | 200, 404, or 409 |

`MediaInfo` includes `media_id`, `source`, `title`, `description`, `channel`, `channel_url`, `duration`, `thumbnail`, `webpage_url`, `upload_date`, `view_count`, `live_status`, `availability`, and `format_count`. Unknown metadata is null. `FormatsResponse` includes `media_id`, `source`, `formats`, and `options`. Each source format reports actual yt-dlp fields and `has_video`/`has_audio`. Output options are separately labeled and may require conversion or audio merging. Source bitrate values are in kbps. Each output option retains its prior fields and adds `available` and nullable `unavailable_reason`. These fields describe FFmpeg encoder support even when the worker is disabled. For example, when VP9 encoding is missing, a WebM option reports `"available":false,"unavailable_reason":"Required FFmpeg encoder unavailable: libvpx-vp9"`, while supported MP4 and audio options remain selectable. `/api/status` reports whether the conversion worker can run; job creation still returns 503 while it is disabled.

Video output resolutions come only from selectable source video streams with a valid height, supported source container and codec, and usable audio in the same stream or a separate audio-only stream. Duplicate heights produce one option per output format. The API does not invent intermediate resolutions or claim that conversion improves source quality. Audio output presets require a usable source audio stream and never exceed its reported bitrate; when that bitrate is unknown, the response uses an unnumbered audio option with a quality note. Job creation applies the same stream selection and returns 422 `unsupported_output` for an unavailable quality or 422 `unsupported_source` for an analysis belonging to another media ID. The worker checks yt-dlp's final selected stream IDs, video height, codecs, and audio bitrate before media download; changed or missing streams fail the job as `Download failed`.

`POST /api/analyze` accepts a browser JSON body such as `{"url":"https://www.youtube.com/watch?v=dQw4w9WgXcQ&t=42s&list=PL123"}`. It extracts exactly one `v` value, discards other query parameters, and passes only the canonical watch URL to yt-dlp. Short links, Shorts, and live URLs may also contain share parameters; duplicate video IDs and playlist-only URLs return 422.

`CreateJobRequest` uses the 11-character YouTube `media_id`, output `format` (`mp4`, `webm`, `mp3`, `m4a`, or `opus`), either `resolution` or `audio_bitrate_kbps`, `include_metadata`, `include_subtitles`, and `confirm_rights`. The caller must affirm permission to process the media; the application cannot verify that claim or platform-term compliance. Subtitles are rejected with 422 because this worker does not implement them. Video conversion requires a real video and audio stream. Output choices must match the latest server analysis. An unavailable output encoder returns 422 with `unsupported_encoder`; a closed worker readiness gate returns 503 with `worker_unavailable`. Example request: `{"media_id":"dQw4w9WgXcQ","format":"mp4","resolution":"1080p","include_metadata":true,"include_subtitles":false,"confirm_rights":true}`. A queued response includes `job_id`, `state`, `progress`, `created_at`, and the selected output. Subsequent responses also include download and conversion progress, timestamps, safe error text, and a download URL only when complete.

State transitions are `queued → downloading → processing → completed`, with `failed` or `cancelled` terminal exits. Restarted unfinished work becomes `failed` with `Interrupted by service restart`. SSE events use `id: VERSION`, `event: job`, and a JSON `data:` line. EventSource automatically sends `Last-Event-ID` when reconnecting. The server responds with `X-Accel-Buffering: no`; Nginx buffering must also allow streaming for this path. `GET /api/jobs` includes completed, failed, and cancelled jobs for the same session, up to 20 records. Without a valid `ytconvert_session` cookie it returns `{"jobs":[]}`; the endpoint does not expose all persisted jobs. The cookie and server-side job authorization expire after `MEDIA_SESSION_TTL_HOURS` from job creation, but the JSON records remain on disk. Output cleanup after `MEDIA_OUTPUT_RETENTION_HOURS` does not remove JSON records.

SSE sends the current state immediately, including on reconnection, then emits changed versions until a terminal state closes the stream. An identical active job for the same session, media ID, output format, and quality returns 409 `duplicate_job`. Download responses use `video/mp4`, `video/webm`, `audio/mpeg`, `audio/mp4`, or `audio/ogg` as appropriate, with a title-based attachment filename, `Content-Length`, and `Cache-Control: private, no-store`. For example, `Beautiful Music - Live Performance.mp4` is sent as `Content-Disposition: attachment; filename*=utf-8''Beautiful%20Music%20-%20Live%20Performance.mp4`. Unicode names use the same UTF-8 encoding. The internal file stays `result.EXT`; older jobs without a stored title use the media ID or `result`. Incomplete jobs return 409 to the matching session. Server clients must send the same job session cookie to access the file. `INTERNAL_IP_RANGES` gates creation only; it does not gate these session-scoped read, event, cancellation, or download endpoints.

Failed jobs retain the last progress values and expose a safe `error` string through job status and SSE. New errors distinguish `Download failed`, `Audio merge failed`, `Source inspection failed`, `Audio extraction failed`, `FFmpeg conversion failed`, `Conversion timed out`, `Output validation failed`, and `Output finalization failed` where the responsible stage is known. Unknown failures report `Conversion failed`. Internal exit codes, exception types, and redacted stderr appear only in server JSON logs, not in API responses. Older records may still contain `Conversion failed or timed out`.
