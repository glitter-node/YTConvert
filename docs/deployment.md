# Deployment handoff

This is a host-specific deployment example, not a public conversion-service template or a verified configuration for another operator. Each operator installs and manages their own instance, access controls, lawful processing decisions, privacy practices, and deployment security. This repository does not change systemd, Nginx, DNS, TLS, firewall, or existing services. The user applies and verifies deployment manually.

Original Glitter.kr-owned YTConvert code is under the root [MIT License](../LICENSE); separately installed dependencies and tools keep their own licenses. See [third-party notices](../THIRD_PARTY_NOTICES.md) before packaging or redistributing an installation. The FFmpeg and ffprobe binaries referenced below are supplied outside this project, and their license depends on the exact build. The inspected host binaries report GPL version 2 or later because GPL components, including libx264, were enabled. No binary redistribution is performed by this deployment guide.

The host-specific `uvi.ytconvert-glitterk.service` example expects the project Python interpreter, `app/main.py`, environment file, and media directories under `/volume1/glitter/ytconvert`. Its `WorkingDirectory` must be the project root, and its environment must expose the values in `data/config/env/ytconvert/.env`. This example assumes a root API process because the current media worker requires root; yt-dlp activity, ffprobe, and FFmpeg inherit that identity. Live service settings were not verified by this documentation. The API writes job records under `data/jobs`, and the worker writes media under `data/temp` and `data/output`. This project does not modify ownership or ACLs.

The ASGI command is:

```bash
/volume1/glitter/ytconvert/venv/bin/python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8010 --workers 1 --lifespan on --log-level info --proxy-headers --forwarded-allow-ips 127.0.0.1
```

`APP_ALLOWED_HOSTS` includes `ytconvert.glitter.kr`, loopback IP, and localhost. Nginx should preserve the public `Host` header and forward requests over loopback. Only the trusted loopback proxy may supply forwarded headers. If Nginx forwards client IPs, it should overwrite untrusted incoming forwarding headers so API rate limits cannot be spoofed. SSE requires buffering to be disabled for `/api/jobs/*/events`, a sufficient proxy read timeout, and forwarding of the session cookie. No proxy setting was changed here. The user starts the existing service or development alias and checks `/api/health`, `/api/status`, and the UI. Default tests do not download media or run FFmpeg.

Worker activation requires a root API process, readable `/opt/bin/ffmpeg`, ffprobe, at least one supported output encoder set, and project directory access. `MEDIA_WORKER_ENABLED` defaults to false in the application and `.env.example` and is the only worker activation flag. Runtime readiness does not verify legal permission or deployment safety. `MEDIA_WORKER_NETWORK_ISOLATED` is no longer used; remove old entries manually if present. This application does not implement or verify outbound network isolation. Existing root execution and outbound access are unchanged. CPU, virtual address space, open-file, per-file size, and wall-clock limits are described in [architecture.md](architecture.md); they are not a sandbox. `MEDIA_WORKER_UID` and `MEDIA_WORKER_GID` are no longer used. A prior check on this host found `/opt/bin/ffprobe` 6.1.4 and no `libvpx-vp9` in the FFmpeg encoder list; recheck the installed binaries before relying on WebM availability. MP4, MP3, M4A, and Opus outputs can pass the encoder check when their required encoders are present. A compromised root worker could read or change files outside this project despite application-level path checks and resource limits.

The host Python standard library has an incomplete `sqlite3` package. The metadata service supplies the version attribute yt-dlp expects at import time and does not use cookie or SQLite features. This is a host compatibility workaround, not a substitute for a complete Python runtime. yt-dlp's network redirects and DNS behavior are not fully isolated in-process. Inbound IP blocking does not mitigate this outbound risk.

An internet-reachable reverse proxy must forward the intended Host header and overwrite untrusted forwarding headers. Uvicorn's `--forwarded-allow-ips 127.0.0.1` is the trust boundary for `request.client`; the API middleware does not parse `X-Forwarded-For` or `X-Forwarded-Host` itself. A separate legacy protection path for `robots.txt` and `sitemap.xml` uses the trusted-proxy resolver in `app/core/ip_resolver.py`. `APP_ALLOWED_HOSTS` validates the Host header but does not authorize a client IP. `APP_IP_BLOCKLIST_FILE` must resolve inside this project and contain a JSON array such as `["203.0.113.0/24", "2001:db8::/32"]`. The file is optional when no block rules are needed. Invalid replacement content retains the last valid list and logs a warning; invalid initial content denies HTTP requests. This blocklist has no effect on yt-dlp traffic. Production OpenAPI routes stay disabled even if `APP_ENABLE_OPENAPI=true`; development can enable them explicitly. No Nginx or service setting was changed here.

Set `INTERNAL_IP_RANGES` in the project environment file to approved client IP addresses or CIDRs, separated by commas. An empty or missing setting denies every `POST /api/jobs` request with HTTP 403; malformed entries prevent startup. The similarly named `INTERNAL_IP_RANGES` in `data/config/_conf_.py` is a host-specific legacy setting for `robots.txt` and `sitemap.xml`, not the conversion gate. This gate does not cover metadata analysis or existing session-scoped job, SSE, cancellation, and download endpoints. The `/api/status` worker capability is a readiness signal, not a client authorization result. The conversion gate uses `request.client.host` after Uvicorn's loopback-only proxy header processing. Nginx must overwrite incoming `X-Forwarded-For` with the actual peer address (or construct a trusted chain that cannot be controlled by the client), and must not pass client-supplied forwarding values as the asserted client IP. Confirm this behavior and that Uvicorn is reachable only over loopback before enabling conversion. This repository cannot verify the live Nginx configuration. A service restart is required to load a changed environment file or updated code.

After explicit approval and after the operator verifies copyright permissions, applicable platform terms, and any relevant technical protection measure rules for a short video, an in-process E2E check can be run without changing the persistent `.env`: `venv/bin/python -m tests.manual_e2e --url 'https://www.youtube.com/watch?v=VIDEO_ID' --confirm-rights`. This script temporarily enables the worker only in its own process, tests analysis, formats, MP4 and MP3 jobs, SSE, downloads, ffprobe, cancellation, and error responses. It retains new job records and outputs for inspection; it does not delete existing data or start Uvicorn. Run only one E2E script at a time. The root worker has unrestricted outbound network access and its yt-dlp host allowlist is not a network sandbox.

The operator can use `synoacltool -get /volume1/glitter/ytconvert/data/temp`, `synoacltool -get /volume1/glitter/ytconvert/data/output`, `/opt/bin/ffmpeg -hide_banner -encoders`, and a read-only ffprobe version check to assess readiness. Account, ACL, FFmpeg, Nginx, and service changes are outside this project's scope. The existing root API service is a residual risk for Phase 2 metadata requests; root media downloads increase that risk further.
